    Installer votre SaaS photobooth

    Cette page vous guide pas à pas, sans connaissances techniques. Comptez une heure la première fois. Cochez « Fait » à chaque étape : votre avancement est gardé dans ce navigateur.

    Vos mots de passe restent chez vous. Cette page fonctionne sur votre ordinateur, même sans Internet. Les mots de passe, clés et jetons que vous saisissez ne sont jamais enregistrés ni envoyés : ils servent seulement à créer le fichier de configuration instance.env. Les autres champs et les cases cochées sont mémorisés dans ce navigateur.

    Ordinateur choisi : Windows (modifiable en haut de la page). Les commandes s'adaptent.

    Jamais utilisé GitHub ni un terminal ? Lisez d'abord premiers-pas.md : pas besoin de compte GitHub, et ce que fait vraiment l'installation.

    Guides détaillés : installation.md (vue d'ensemble et coûts), installation-instance.md (le SaaS), installation-borne.md (la borne).

    Commencer
    1

    Installer les outils

    5 min

    Il faut Node.js (version 20 ou plus récente) pour lancer l'installation. Git est conseillé : il simplifie les mises à jour (facultatif si vous téléchargez le code en ZIP).

    Le plus simple : une seule commande

    1. Ouvrez l'invite de commandes : touche Windows, tapez cmd, puis Entrée.
    2. Collez cette commande (clic droit dans la fenêtre), puis Entrée. Acceptez les questions éventuelles.
    winget install OpenJS.NodeJS.LTS Git.Git
    1. Fermez la fenêtre quand c'est terminé (les outils ne sont reconnus que dans une nouvelle fenêtre).

    Ou par téléchargement

    Télécharger Node.js (LTS) Télécharger Git pour Windows

    Gardez les options proposées par défaut pendant l'installation.

    Avec les installeurs (le plus simple)

    1. Téléchargez et installez Node.js, version « LTS » (fichier .pkg).
    2. Pour Git, ouvrez le Terminal (Cmd + Espace, tapez « Terminal », Entrée) et lancez la commande ci-dessous. Une fenêtre propose d'installer les outils : acceptez.
    Télécharger Node.js (LTS) 
    xcode-select --install
    Vous utilisez Homebrew ? 
    brew install node git
    1. Node.js : suivez la page de téléchargement officielle (choisissez Linux). Les versions fournies par les distributions sont souvent trop anciennes.
    2. Git, dans un terminal (Debian, Ubuntu) :
    Télécharger Node.js (LTS) 
    sudo apt install git

    Fedora : sudo dnf install git.

    Vérifier

    Dans une nouvelle fenêtre de terminal, cette commande doit afficher v20 ou plus :

    node --version

    Pas besoin d'installer la CLI Supabase : le script s'en charge.

    Récupérer le code

    2 min

    Vous lisez cette page depuis le dossier du code : cette étape est faite. Le dossier saas se trouve ici :

    {SAAS_DIR}

    Sinon, deux façons de récupérer le code depuis la page GitHub de Polabooth :

    • En ZIP (sans Git) : bouton vert « Code » > « Download ZIP ». Décompressez le fichier dans un dossier simple (par exemple Documents), puis ouvrez docs/guide-installation.html par un double-clic pour retrouver cette page.
    • Avec Git (mises à jour plus simples) : copiez l'adresse affichée par le bouton « Code », puis dans un terminal :
    git clone <adresse copiée>

    Évitez un dossier synchronisé (OneDrive, iCloud) : l'installation y crée beaucoup de petits fichiers.

    3

    Créer le projet Supabase

    10 min

    Supabase remplace le serveur : base de données, comptes, fonctions. Vous n'avez aucune machine à gérer. L'offre gratuite suffit pour essayer ; pour une vraie activité, prenez l'offre Pro (la gratuite met le projet en pause après une semaine sans activité).

    1. Créez un compte (ou connectez-vous), puis cliquez sur New project.
    2. Donnez un nom au projet, choisissez une région en Europe (Paris ou Francfort).
    3. Mot de passe de la base : cliquez sur « Generate a password », copiez-le et collez-le ci-dessous avant de valider.
    4. Une fois le projet créé, copiez l'adresse de la page du navigateur et collez-la dans « Identifiant du projet » : la page en extrait l'identifiant (20 lettres).
    Ouvrir Supabase Réglages du projet

    Le jeton d'accès

    Il permet au script de régler Supabase à votre place (adresse du site, emails, sécurité des mots de passe). Page des jetons > Generate new token, nom « polabooth ». Copiez-le aussitôt : il ne s'affiche qu'une fois.

    Créer un jeton d'accès
    Mot de passe de la base oublié ?

    Database > Settings > « Reset database password ». Mettez le nouveau dans le champ ci-dessus.

    Réglages de la base
    4

    Préparer le stockage des photos

    15 min

    Les photos des bornes sont rangées dans un stockage « compatible S3 ». Les invités les ouvrent directement depuis ce stockage. Conseillé : Cloudflare R2 (10 Go gratuits, aucun frais quand les invités regardent les photos).

    Cloudflare R2, pas à pas

    1. Ouvrez R2 dans le tableau de bord Cloudflare et activez-le (une carte bancaire est demandée, rien n'est prélevé sous les quotas gratuits). L'Account ID est affiché sur cette page : collez-le ci-dessous.
    2. Create bucket : nom medias, emplacement « Automatic » ou « European Union ».
    3. Dans le bucket > Settings > Public access :
      • domaine personnalisé (conseillé) : « Connect Domain », par exemple medias.mon-entreprise.fr (le domaine doit être géré par Cloudflare) ;
      • ou adresse r2.dev : « Allow Access » (https://pub-….r2.dev, limitée en débit : pour les essais).
      Notez cette adresse publique : elle doit commencer par https://.
    4. Manage R2 API Tokens > Create API token : permission « Object Read & Write », limitée au bucket medias. Copiez l'Access Key ID et la Secret Access Key (affichée une seule fois).
    Ouvrir R2 Jetons d'API R2
    Remplit l'adresse S3 (https://<Account ID>.r2.cloudflarestorage.com) et la région (auto).
    Autre fournisseur (Scaleway, OVHcloud, Backblaze, MinIO)

    Créez un bucket en lecture publique (adresse en https://) et une clé d'accès en lecture et écriture, puis choisissez votre fournisseur : l'adresse S3, la région et l'adresse publique sont pré-remplies (à vérifier chez lui).

    Réglages avancés (facultatifs)

    Règle CORS

    Elle autorise votre SaaS à envoyer des fichiers dans le bucket. Le script la vérifie pendant l'essai et essaie de la poser lui-même pendant l'installation. Une clé R2 « Object Read & Write » n'en a pas le droit : dans ce cas, ou si le script vous le dit, collez-la dans le bucket > Settings > CORS Policy :

    [
  {
    "AllowedOrigins": ["{APP_URL}"],
    "AllowedMethods": ["GET", "PUT"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
    5

    Régler la messagerie

    5 min

    Les emails (photos aux invités, échanges avec vos clients, alertes des bornes) partent de votre adresse, par le serveur SMTP de votre messagerie. Demandez à votre hébergeur email les réglages « SMTP SSL/TLS, port 465 ».

    Port 465 obligatoire. Supabase bloque les ports 25 et 587.

    MessagerieServeur SMTPRemarque
    IONOSsmtp.ionos.frIdentifiant : l'adresse email complète.
    OVHcloudssl0.ovh.netIdentifiant : l'adresse email complète.
    Gmail, Google Workspacevoir l'aide de GoogleMot de passe d'application (validation en deux étapes requise) ; nombre d'envois limité par jour.

    Pendant l'essai (étape 7), le script envoie un email de test à l'adresse de l'administrateur : vous saurez tout de suite si ces réglages fonctionnent.

    6

    Votre SaaS et le fichier de configuration

    5 min

    Choisissez l'adresse de votre SaaS : un sous-domaine de votre site suffit, par exemple https://photobooth.mon-entreprise.fr. Vous le relierez à l'hébergement à l'étape 8.

    Mise en ligne automatique du site (facultatif)

    Indiquez votre hébergeur si vous voulez que npm run update-instance remette le site en ligne tout seul à chaque mise à jour (étape 8 et « Plus tard »). Laissez vide pour déposer le dossier dist vous-même. Modifiable ensuite dans instance.env.

    Vérification

      Les mots de passe ne sont pas gardés : si vous rechargez la page, saisissez-les de nouveau avant de télécharger le fichier.

      Plus tard : mettre à jour
      
      
      
      
      
        
      Pour être prévenu d'une nouvelle version : sur la page GitHub de Polabooth, Watch > Custom > cochez Releases.
          Chaque version a ses notes (ce qui change, ce qu'il reste à faire à la main). La version installée s'affiche en bas du menu du compte, dans l'admin.
      
        
      Avec Git (une commande)
      
        
      cd /d "{SAAS_DIR}"
npm run update-instance
      
        
      cd "{SAAS_DIR}"
npm run update-instance
      
        
      La commande récupère la nouvelle version, s'arrête avant tout changement si vous avez modifié des fichiers du dépôt (elle les liste),
          installe les outils, met à jour la base et les fonctions, puis remet le site en ligne si HOSTING est rempli (sinon, refaites l'étape 8).
          Elle affiche la version avant et après, et les actions à faire à la main. Une erreur ? Corrigez, relancez : elle reprend où elle s'était arrêtée.
      
        
      Ne modifiez que instance.env : il n'est jamais touché par la mise à jour. Relancer l'installation (npm run install-instance) reste sans risque, par exemple après un changement d'instance.env.
      
        
      Avec un ZIP
      
        
      Téléchargez et décompressez la nouvelle version, copiez votre saas/instance.env dans son dossier saas, puis lancez son programme d'installation (étape 7)
          et remettez le dossier dist en ligne (étape 8).
